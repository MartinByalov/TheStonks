# The Stonks — генератор на пикселови NFT изображения

Клиентски (браузърен) генератор, който композира пиксел-арт (24×24px)
слоеве в **10 000 гарантирано уникални** персонажа — "Stonk"-ове, плюс
процедурно нарисувана "борсова" линия на фона. Няма нужда да пазиш 10 000
PNG файла: изображенията се композират в реално време от малкото изходни
слоеве, а кой точно трейт получава всеки номер е предварително изчислено
и записано в JSON.

## Структура

```
The_Stonks_Generator/
├── index.html                  ← демо страница (бутон → модал с прозорец)
├── js/
│   └── stonk-generator.js      ← самият генератор (ES модул, 0 dependencies)
├── data/
│   ├── traits-config.json      ← слоеве, ред, rarity тежести
│   └── stonks-collection.json  ← 10 000-те предгенерирани уникални комбинации
├── assets/                     ← 24×24 PNG слоеве (background, body, hat, dress...)
├── tools/
│   └── build_bodies.py         ← скрипт, който изрисува 7-те стандартизирани тела
└── generate-collection.mjs     ← Node.js скриптът, който произвежда stonks-collection.json
```

Целият проект е **чист JavaScript** в частта, която тича на сайта
(`stonk-generator.js` + `index.html`). `generate-collection.mjs` (Node.js)
и `tools/build_bodies.py` (Python) са еднократни build-инструменти — пускат
се само локално, никога на самия сайт, и не са нужни на посетителите.

## Как работи

1. **`traits-config.json`** описва категориите слоеве (фон, тяло, облекло,
   аксесоар на тялото, очи, лицева черта, шапка, аксесоар в ръка), реда, в
   който се рисуват (отдолу нагоре), и относителната тежест (rarity) на
   всяка опция. Категорията `chart` е специална — вместо PNG файл, тя
   съдържа стил (`uptrend`/`downtrend`/`choppy`), използван за процедурно
   рисуване (виж по-долу).
2. **`generate-collection.mjs`** е еднократен build-скрипт (`node
   generate-collection.mjs`). Хвърля претеглен зар 10 000 пъти, като при
   евентуално повторение на комбинация просто пробва пак — резултатът е
   `stonks-collection.json`, гарантирано 10 000 уникални комбинации
   (проверено programmatically при всяко пускане).
3. **`stonk-generator.js`** е това, което реално тича в браузъра на
   посетителите — чете готовата таблица за даден `tokenId` (1–10000) и:
   - рисува фона (pixel-art, `imageSmoothingEnabled = false`);
   - **процедурно рисува** гладка червено/зелена "борсова" линия отгоре на
     фона (виж следващата секция);
   - композира тялото + всички аксесоари (pixel-art) най-отгоре.

Понеже подредбата е предизчислена, резултатът е **детерминиран**: Stonk
#4242 винаги ще изглежда по един и същ начин за всички посетители.

## Графиката на фона вече е истинска линия, не pixel-art

Преди: `chart1.png`/`chart2.png` бяха статични пикселови спрайтове (само
2 варианта). Сега `drawChartLine()` в `stonk-generator.js` рисува линията
**директно на финалния `<canvas>`**, с включено `imageSmoothingEnabled =
true` само за тази стъпка — гладка, тънка линия, контрастираща с острите
пиксели на героя, точно както при истинска борсова графика.

- Пътят се генерира от seeded PRNG (`mulberry32`), seed-нат с
  `tokenId + стил`, така че е **детерминиран** (Stonk #4242 винаги ще има
  същата линия), но изглежда като случайно движение нагоре/надолу.
- 3 стила, избирани чрез същата тежинна система като другите трейтове:
  - `uptrend` — линията клони нагоре (повече зелени сегменти)
  - `downtrend` — клони надолу (повече червени)
  - `choppy` — балансирано движение и в двете посоки
  - `null` ("Няма") — без линия
- Всеки сегмент е зелен, ако цената се качва спрямо предходната точка, и
  червен, ако пада — както при истинска candlestick графика.

Ако искаш друг вид линия (напр. свещи вместо права линия, повече точки,
различни цветове), редактирай `drawChartLine()` — параметрите
(брой точки, дебелина, отклонение) са в началото на функцията.

## Тела: стандартизирана геометрия (фикс на разминаванията)

Оригиналните 7 "candle" тела бяха рисувани с различна височина на главата
(0 до 6 реда разлика между вариантите), заради което шапки/очи/лицеви
черти или "увисваха" във въздуха, или не съвпадаха с лицето при различни
комбинации.

Решението вече не е компенсация чрез офсети (крехко, лесно се чупи при
нов ресурс) — **всичките 7 тела са пренарисувани от нула** с абсолютно
еднаква геометрия: фитил горе (rows 1-2), тяло (rows 3-10, очи на row 5,
уста на row 8), фитил долу (rows 11-21). Различават се само по цвят/нюанс
(зелено/червено/златно) — виж `tools/build_bodies.py`. Резултат: **всеки**
hat/eyes/facefeature/dress пасва на **всяко** тяло по конструкция, без
никакъв рънтайм код за корекция. Провалидирано на 40+ случайни номера от
готовата колекция — без нито едно разминаване.

Ако искаш да добавиш ново тяло (напр. осми цвят), просто добави нова
палитра в `PALETTES` в `tools/build_bodies.py` и пусни `python3
tools/build_bodies.py` — геометрията се поема автоматично от шаблона.

## Премахнат недовършен елемент

`facefeature4.png` ("сълзи" — малки сини точки) се оказа нефункционален —
виси откъснат над главата при всяко тяло. Премахнат физически от
`assets/facefeature/` и от `traits-config.json`.

Оригиналната `candlebody2 hats/hat1.png` (звездно-раирана шапка от
изходния ZIP) беше позиционирана за тяло-вариант, който не съществуваше в
пакета — не е включена в генератора.

## Интеграция в твоя сайт (Easter egg бутон)

1. Качи цялата папка (`assets/`, `data/`, `js/`) някъде в твоя сайт, напр.
   `public/stonks/`.
2. В твоя JS:

```html
<script type="module">
  import { StonkGenerator } from '/stonks/js/stonk-generator.js';

  const gen = new StonkGenerator({ basePath: '/stonks' });
  await gen.load(); // зарежда config + collection веднъж, при старт

  document.getElementById('easterEggBtn').addEventListener('click', async () => {
    const id = gen.randomId();                 // случаен номер 1..10000
    const info = gen.getStonk(id);              // име на трейтовете + rarity rank
    await gen.render(id, myCanvasElement, { size: 400 });
    // покажи myCanvasElement в своя си модал/прозорец
  });
</script>
```

3. `index.html` в тази папка е готово демо на точно това поведение
   (бутон → изкачащ прозорец с canvas + списък трейтове + rarity rank) —
   отвори го през локален сървър (`npx serve .`), за да видиш ефекта, и
   копирай каквото ти трябва в разметката на твоя сайт.

### Полезни методи на `StonkGenerator`

| Метод | Какво прави |
|---|---|
| `await gen.load()` | Зарежда `traits-config.json` + `stonks-collection.json`. Извиква се веднъж. |
| `gen.randomId()` | Връща случайно число 1–10000. |
| `gen.getStonk(id)` | Връща `{ id, traits[], rarityScore, rarityRank, totalSupply }` — без нужда от canvas. |
| `await gen.render(id, canvasEl, { size })` | Композира и рисува Stonk #id върху даден `<canvas>`. |
| `await gen.preloadAll()` | По избор — зарежда всички PNG слоеве предварително, за по-бърз първи рендер. |

## Промяна на rarity / пренареждане на колекцията

Тежестите на всеки трейт са в `data/traits-config.json` (полето `weight`,
и `noneWeight` за "без трейт"). След промяна пусни:

```bash
node generate-collection.mjs
```

за да прегенерираш `stonks-collection.json`. Смени `COLLECTION_SEED` в
скрипта, ако искаш различна подредба при същите тежести.

**Забележка:** при прегенериране конкретен `Stonk#` ще получи различна
комбинация от преди (разбъркването се променя) — самите изображения и
разнообразието остават същите, просто номерата се разбъркват наново.
